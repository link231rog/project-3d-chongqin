# 开发交接

交接日期：2026-10-18，Asia/Shanghai。

## 当前目标与状态

用户希望尽可能精细还原整个渝中半岛，并在此模型上做三维地图导航。每建一处先核实资料。这个目标尚未完成。当前已采集2032个建筑轮廓、2890段道路/步道；普通建筑已加程序立面图集和屋顶设备，但仍是轮廓拉伸，缺少逐楼核实的高度、实拍立面和屋顶细节；道路快照尚缺导航所需的单行、车道和拓扑标签。

项目包含依赖、构建产物、测试与完整源码。开发及历史演进记录如下。

## 用户最近的重点反馈

1. 旋转时水面抖动、闪动。
2. 整体精度和呈现效果不如昨天版本。
3. 长江、嘉陵江分别使用稳定颜色，合流后延续长江颜色。

不要继续只加数量。先确认旋转和近景观感，再挑一个街区或地标补细节。不要删除真实地图以换回随机摆放楼群。

## 最近已做的修复

- 开启 `logarithmicDepthBuffer`，相机 near 从0.1调为0.5；水面 shader 接入完整 logdepth 顶点和片元 chunks。
- 水面改为固定平面，取消顶点动画和随视角跳变的镜面闪点；片元内逐像素计算视线方向与菲涅耳，只做低强度天空反照，噪声图案固定在世界坐标并沿江向拉伸。
- 用真实嘉陵江水域轮廓生成分色 mask；长江 0x6f5f3f、嘉陵江 0x2f5d55，朝天门尖端以东统一长江色。
- 清除通用模型重复绘制的来福士8栋塔楼和水晶连廊。之前这些白色拉伸体遮住了自定义模型。
- 来福士白色横条纹的根因是46/77段盒体间1.5%缝隙透出天空，改为1.01倍重叠；删除全深度中央脊和两侧边梃，避免斜视时出现整面白墙。玻璃提高粗糙度、降低clearcoat，减少过曝。
- 水晶连廊从塔前 z=6.0 移回前四塔中心线 z=2.82；观景台移到连廊端部并缩小；连廊半径 2.6→2.05，材质去饱和。

- 双击本地 HTML 时跳转到开发服务，避免 file 协议下模块无法加载而一直显示加载页。
- 普通建筑新增4×4立面窗格图集（`src/facade-texture.js`），每栋按ID分配16种窗型；保留三平面UV和远景衰减，避免远处窗格闪烁。
- 普通建筑屋顶增加女儿墙和屋顶设备（InstancedMesh），屋顶不再是纯色平面；设备位置和尺寸为程序估算，不是实测。

## 已知不足与接手优先级

1. **水面已改善，仍需多角度复核**：已确认无顶点动画和随视角跳变的高光；长江沙褐、嘉陵江灰绿、合流后长江色已在全景/交汇/默认镜头验证。仍需检查贴岸、低角度、夜景和不同设备；噪声是程序近似，不是实测流速。
2. **全景仍粗糙**：建筑覆盖不完整；大量默认18米高度，立面是程序近似，不是测绘模型。已加立面图集和屋顶设备，但整体仍偏浅、稀疏。
3. **来福士仍非精确复原**：白色横条纹和斜视白墙已修复；塔身仍是直箱体（曲线只在Z向，正面看不出）、平顶、无幕墙网格。朝向已由 OSM 连廊轴反解（rotation=-0.3759），8 塔中心与裙楼轮廓按 OSM；楼面高度、平台形状和连廊截面尺寸仍是近似，46/77 分层不等于楼层逐一核实。
4. **地形分辨率有限**：7049个样本的间隔约80—93米，无法还原堡坎和街巷微地形；对岸超出网格时会使用边界高程。
5. **道路需按层级处理**：普通道路贴地，隧道被过滤，bridge 标记道路由专门模型接管；不能认为整个立体路网已连通。局部路段与岸线也需查错。
6. **桥梁仍有近似**：新桥的桥面高程、主墩沿线位置、构件截面/墩形部分估算；曾家岩站桥换乘设施未完成。渝澳、黄花园、嘉华、红岩村等仍待按资料补建。
7. **城市细节**：滨江挡墙、护岸、码头、通远门、罗汉寺、红岩村等大量区域尚未精细完成。
8. **画面验证待系统化**：旧截图仅供审美比较，不作为当前版本准确性基准。构建有大包体积提示，尚未做拆包或移动端性能保证。
9. **导航数据只有采集契约**：`tools/nav_extract.py` 定义了原始 OSM 道路/节点/转向限制的导出格式，`tools/fixtures/osm-nav-elements.json` 是手写 fixture，不是真实路网；`tools/nav-sample.json` 也只是该格式的样例。要支持导航，仍需联网重新采集完整 OSM 标签（oneway/lanes/width/surface/node IDs）并构建带权图、连通性检查和路线测试。采集脚本 `collect-peninsula.py` 依赖 Shapely，本机未安装。
