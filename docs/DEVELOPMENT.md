# 开发与排障

## 本地命令

在项目根目录运行：

```sh
npm install
npm run dev
npm test
npm run build
npm run preview
```

迁移已保留 `node_modules`，不需要为了启动重复安装。开发固定使用127.0.0.1:5173，生产预览默认4173。修改源文件后Vite会热更新，改HTML通常会刷新页面。

当前无lint脚本、无浏览器自动测试套件、无CI和Git历史。`npm test` 只覆盖高程插值、部分桥梁几何与列车时钟，不覆盖整座城市的视觉准确性。

## 针对性检查

- 改启动/模块导入：构建一次，并确认浏览器加载遮罩退出、控制台没有新错误。
- 改水面/深度：同一环境看朝天门近景、全景、贴岸和低角度；实际旋转，检查黑斑、闪点和边界跳动。
- 改精模：检查通用建筑有无重复覆盖，检查旋转后的背面和底座，别只看单张正面图。
- 改夜景：切换日间、晚霞、赛博，检查灯带位置、透明光束与玻璃遮挡。
- 改动画：暂停后时间不跳、恢复后不突然追帧，方向键不与镜头Tween互相拉扯。
- 改合影：默认不显示；点击打开后才初始化；背景切换后能定格，导出只含相框和人像。

每次检查先明确要发现什么故障。通过后不要没有新理由地重复整套检查。

## 常见问题

**一直在加载**：确认地址是HTTP服务而非file协议。主入口模块依赖Vite解析包与JSON；双击文件不能独立运行。其次看控制台是否有模块、解压或WebGL错误。`init().catch()` 目前只给通用失败文案，后续可改为具体加载阶段和可读错误。

**5173被占用**：先找现有项目服务，不要再启动多个实例。当前开发命令启用了 `--strictPort`，不会切换到另一个端口造成浏览器仍打开旧服务。

**水面旋转时出现黑色碎片**：先看对数深度是否开启，以及水面顶点/片元shader是否都有对应chunks。整个半岛尺寸下不能照搬小场景的深度设置；不要只调水色或把粒子关掉就认为修好。

**来福士变成多组白墙**：确认 `peninsula.js` 的通用生成器排除了水晶连廊和T1—T6各塔楼；这些已有自定义精模。不要用大范围删楼掩盖定位问题。

**远处窗格闪烁**：保留 `fwidth` 抗锯齿和远景细节衰减。细窗格不能在极远视角使用硬阈值采样。

## 数据采集工具

保留了两份历史采集脚本，均只输出到标准输出，不会自动覆盖运行时JSON。此次迁移未重新联网执行它们。

- `tools/collect-peninsula.py`：请求OSM八个地图瓦片、区界和河流关系；需要Python与Shapely。输出 `SUMMARY:` 和 `PAYLOAD:`。移除了原来依赖 `/tmp` 的Python库路径。
- `tools/collect-elevation.py`：请求Open Topo Data的SRTM30m接口，分100点批次获取7049点，批次间隔1.05秒。输出 `PROGRESS:`、`SUMMARY:`、`DATA:`。不要在普通测试里调用外部API。

按需准备工具环境：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install shapely
.venv/bin/python tools/collect-peninsula.py
.venv/bin/python tools/collect-elevation.py
```

脚本重新获取的是当时最新的外部数据，不保证重现旧快照。替换运行资源前核对完整性、轮廓/路段数、坐标、闭合环、资源格式和自定义模块依赖的OSM ID。`PAYLOAD`/`DATA` 应包装为现有 `{encoding, data}` 格式；不是把整段日志直接存成JSON。

其他公园、线路、水域裁剪数据是独立快照，尚无统一的一键生成器；来源ID及限制见 `SOURCES.md`。临时Python环境不随项目迁移，浏览器运行不依赖Python或Shapely。
